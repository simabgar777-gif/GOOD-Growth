# Гео-аналитика: что можно, чего нельзя и как сделать честно

Черновик решения для Капитана. Подготовлен ночью 27.11, к обсуждению утром.

## 1. Вопрос

«Можно ли видеть, откуда пришёл человек — страна, город, женщина или мужчина?»

## 2. Короткий ответ

| Что | Возможно? | Как | Надёжность |
|---|---|---|---|
| Страна | да | по IP-адресу (локальная база GeoIP или внешний сервис) | ~99% |
| Город | да, но грубее | по IP | ~70–85% (мобильные операторы врут) |
| Часовой пояс | да | по IP или `Intl.DateTimeFormat().resolvedOptions().timeZone` | высокая |
| Язык | да | `navigator.language` + выбор языка в шапке | высокая |
| Устройство, браузер | да | User-Agent (мобильный/десктоп/планшет) | высокая |
| Источник перехода | да | `document.referrer`, UTM-метки, партнёрский `?ref=` | высокая |
| **Пол** | **нет** | технически определить нельзя | — |
| Пол (сам указал) | да | необязательный вопрос в онбординге | честно, но заполняют редко |

**Пол по IP, устройству или имени — это гадание.** По имени ошибаются в 20–30% случаев
(«Александр/Александра», «Саша», «Женя», иностранные имена), а ошибка в обращении
оскорбляет человека сильнее, чем отсутствие обращения. GOOD так не делает.

## 3. Правовая сторона — важнее технической

```
IP-адрес = персональные данные (GDPR, 152-ФЗ, закон Армении).
```

Что это значит на практике:

- **Хранить агрегаты безопасно.** «Сегодня 40 визитов из Армении» — не персональные
  данные. «Этот человек из Еревана» — уже персональные данные.
- **Сырые IP не храним.** Определили страну → записали страну → IP забыли.
- **Согласие уже есть** через cookie-баннер, но его стоит расширить формулировкой
  «обезличенная статистика посещений».
- **Пол — только если человек сам указал.** Иначе никак.

## 4. Что предлагаю сделать

### А. «Откуда приходят» — карточка в аналитике

```
🌍 Откуда приходят
Армения      42%   ▓▓▓▓▓▓▓
Россия       31%   ▓▓▓▓▓
Грузия        9%   ▓▓
Другое       18%   ▓▓▓

устройства: телефон 61% · компьютер 34% · планшет 5%
языки:      русский 78% · английский 14% · армянский 8%
```

Только агрегаты по дням. Никаких имён, IP, адресов.

### Б. Технически — как считать

```
1. nginx уже отдаёт X-Forwarded-For → server.js видит IP запроса
2. Определяем страну: локальная база GeoLite2 (бесплатно, без внешних запросов)
   или один запрос к ipapi.co с кэшем по хешу IP на сутки
3. Пишем ТОЛЬКО: день, страна, город (опционально), тип устройства, язык
4. IP хешируем с солью для дедупликации — сам IP не сохраняется
5. API: GET /api/analytics/geo → агрегаты за 30 дней
6. Карточка в аналитике — рядом с «По брендам»
```

Объём: один вечер. Всё обратимо, без внешних сервисов, без персональных данных.

### В. Пол — только по желанию человека

Если бизнесу нужен пол (например, для тональности текста), единственный честный путь —
необязательное поле в онбординге:

```
«Как к тебе обращаться?»  →  он/она/просто по имени
```

И честная подпись: «необязательно, нужно только для обращения в текстах».
Заполнят человек 30 — и это будут честные 30%, а не выдуманные 100%.

## 5. Зачем это бизнесу GOOD (не «просто интересно»)

```
1. Оплаты: разные платёжки для RU / AM / EU — надо знать, откуда люди
2. Цены и языки: в Армении и России разная чувствительность к цене
3. Партнёрка: видеть, из какой страны приходят клиенты партнёра
4. Контент: понимать, на каком языке писать и в какое время публиковать
5. Инвесторы и отчёты: «нас читают в 12 странах» — сильная фраза, если она правда
```

## 6. Что нужно решить Капитану

```
1. Включаем гео-карточку? (мой голос — да, только агрегаты)
2. Город нужен или хватит страны? (город врёт на мобильных)
3. Нужен ли пол? Если да — только необязательным вопросом в онбординге
4. Формулировка в cookie-баннере: добавить «обезличенная статистика посещений»?
```

## 7. Чего делать не будем

```
✗ угадывать пол по имени или технике
✗ хранить сырые IP-адреса
✗ собирать данные без согласия
✗ показывать человеку «мы знаем, что ты из Еревана» без его ведома
```

Правда вместо имитации: если данных нет — так и пишем «пока мало данных»,
а не рисуем красивые проценты из воздуха.
