# Как выбрать исполнителя на платёжки — чек-лист

> Для Капитана. Заполняем по каждому отклику на Kwork.

## 1. Что должно быть в отклике (иначе — мимо)

```
☐ Называет срок на КОНКРЕТНЫЙ кусок (ЮKassa + подписки), а не «всё за неделю»
☐ Спрашивает про мерчанта: есть ли магазин в ЮKassa / аккаунт Paddle
☐ Упоминает проверку подписи вебхука (IP-список, HMAC, проверка через API)
☐ Говорит про идемпотентность (повторный вебхук не должен продлевать дважды)
☐ Понимает разницу: платёж ≠ подписка ≠ продление ≠ возврат
☐ Спрашивает, какой стек и где хостинг — или сразу спрашивает доступ
```

## 2. Красные флаги

```
✗ «Сделаю всё за 3 дня» — платёжки так не делаются
✗ «Пришлю готовый модуль» без вопросов про наш код
✗ Не спрашивает про мерчанта и документы
✗ Обещает «оплату картой любой страны» через один сервис
✗ Просит root и полный доступ «чтобы быстрее»
✗ Отказывается от поэтапной оплаты
✗ Не может назвать ни одного кейса с подписками
```

## 3. Вопросы, которые задаём в переписке

```
1. Какие платёжки подключали и на каком стеке? (просим ссылку/скрин)
2. Как проверяете подлинность вебхука у ЮKassa? (правильный ответ: IP-список
   и/или GET /v3/payments/{id} — не «доверяем телу запроса»)
3. Что будет, если вебхук придёт дважды?
4. Как храните подписку: таблица, поля, что при отмене и при возврате?
5. Как проверим, что тариф реально включился? (просим сценарий теста)
6. Работаете по этапам с приёмкой каждого? (правильный ответ: да)
7. Что нужно от нас, кроме ключей? (юрлицо, оферта, тестовые карты)
```

## 4. Как сравниваем отклики (ставим 1–5 по каждому)

| Критерий | Вес | Комментарий |
|---|---|---|
| Кейсы с подписками/вебхуками | ×3 | главный сигнал |
| Понимание подписи вебхука | ×3 | безопасность |
| Спрашивает про мерчанта | ×2 | опыт с реальными запусками |
| Готовность к этапам | ×2 | снижает риск |
| Сроки | ×1 | реалистичность |
| Цена | ×1 | не главное |

**Правило: если по первым двум пунктам 1–2 балла — не берём, даже за 3 000 ₽.**

## 5. Условия, которые ставим мы

```
· оплата по этапам, каждый этап принимается отдельно
· код присылает патчем, деплоим мы (или даём доступ на время этапа)
· доступ: отдельный пользователь, sudo только на systemctl
· перед работой — бэкап; после — смена пароля и отзыв ключа
· в отчёте: что сделано, какие ключи, как откатить
· никаких правок чужих маршрутов и дизайна
```

## 6. Первый этап, на котором проверяем человека

```
Задача: «ЮKassa — создание платежа + вебхук с проверкой подписи
        + включение тарифа при success» на нашем коде.
Объём: 1–2 дня. Оплата: 3 000 – 6 000 ₽.
Приёмка:
  1. тестовая оплата картой в песочнице включает тариф growth;
  2. повторный вебхук не продлевает второй раз;
  3. вебхук с неверной подписью → 400 и тариф не меняется;
  4. в логах нет наших секретов.
Прошёл — даём следующий этап (продление, отмена, кабинет оплаты).
```

## 7. Что фиксируем в переписке письменно

```
· объём этапа и что НЕ входит
· срок и цена
· что считается приёмкой (4 пункта выше)
· что даём со своей стороны и когда (ключи, доступ)
```
