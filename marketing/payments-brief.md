# ТЗ: подключить платёжные системы (RU / AM / Европа) к GOOD Growth

> Для исполнителя на Kwork. Ниже — всё, что нужно знать, чтобы оценить и сделать.
> Заказчик: Альберт, GOOD Growth (growth.go-ood.com).

## 1. Что за проект

- Сайт: **https://growth.go-ood.com** — SaaS «мастерская роста»: цель → разбор → посты.
- Бэкенд: **Node.js, один файл `server.js`** (без Express/Nest), свой роутер `if (req.method === 'GET' && u.pathname === '...')`.
- База: **`node:sqlite`** (`DatabaseSync`), файл `data/goodgrowth.db`. ORM нет.
- Фронтенд: статические HTML + ванильный JS в `/var/www/app` и `public/`.
- Сервер: Ubuntu VPS, **nginx** (конфиг `/etc/nginx/sites-enabled/goodgrowth`), systemd-сервис `goodgrowth`, порт 3000.
- Репозиторий: Node-проект без сборки; зависимостей почти нет.

## 2. Что уже есть в коде

```
GET  /api/payments/providers   → список провайдеров и их методы (готово)
POST /api/payments/webhook/:p  → заглушка: логирует и отвечает {ok:true} (НЕ активирует тариф)
function paymentProviders()    → yookassa / paddle / arca — описаны, ready по env-ключам
таблица plans                  → start 0 ₽ · growth 490 · pro 990 · agency 2990 · unlimited 5990
таблица users                  → есть id, email, …
таблица brands                 → brands_max по тарифу уже проверяется
партнёрская программа          → db.partnerAccrue(code, userId, planCode, price, period)
                                 должна вызываться при успешной оплате (см. п. 6)
```

**Нет:** таблицы подписок, создания платежа, проверки подписи вебхуков, продлений/отмен, чеков, страниц оплаты.

## 3. Что нужно сделать

### 3.1 Подписки (ядро)

Таблица `subscriptions`:

```
id, user_id, plan_code, status (active|past_due|canceled|expired),
provider (yookassa|paddle|arca), provider_ref (id платежа/подписки),
period_start, period_end, auto_renew (0/1), created_at, updated_at
```

Функции (в `db.js`): `getActiveSubscription(userId)`, `upsertSubscription(...)`, `extendSubscription(...)`.
Тариф пользователя берётся из активной подписки; если её нет — `start`.

### 3.2 Россия — ЮKassa

- Методы: карта МИР/Visa/MC, СБП (QR), ЮMoney, SberPay, T-Pay.
- Создание платежа: `POST /api/payments/create` → возвращает `{ pay_url }` (redirect или виджет).
- Вебхук `POST /api/payments/webhook/yookassa`:
  - проверка источника (IP-список ЮKassa или проверка через API `GET /v3/payments/{id}`);
  - события `payment.succeeded`, `payment.canceled`, `refund.succeeded`;
  - **идемпотентность** по `payment.id` (повторный вебхук не должен продлевать дважды).
- Чек (54-ФЗ): передавать `receipt` с email и позицией «Тариф …».
- Автопродление: рекуррентные платежи ЮKassa **или** напоминание + ручное продление (решить с заказчиком).

### 3.3 Европа — Paddle (или Lemon Squeezy / Stripe — на выбор заказчика)

- Checkout через API/ссылку; методы: Visa/MC, Apple Pay, Google Pay, PayPal (если доступно).
- Вебхук: проверка **подписи** (Paddle-Signature, HMAC), события `subscription.created/updated/canceled`, `transaction.completed`.
- Продление и отмена — из событий провайдера; отмена по кнопке в кабинете.

### 3.4 Армения — ArCa / Ameriabank (или Idram)

- Hosted checkout: создание заказа → redirect → callback.
- Callback: проверка подписи/хэша по документации банка; успех → подписка.
- Если у заказчика на момент старта нет мерчанта — сделать адаптер по спецификации и включить, когда дадут ключи.

### 3.5 Фронтенд

- `/pricing` — тарифы и кнопки «Оплатить». Уже есть страница тарифов — встроить оплату.
- Страницы результата: `/payment/success`, `/payment/fail` (простые HTML).
- В кабинете `/app/billing`: текущий тариф, дата продления, «Отменить подписку», история платежей.
- Показывать только доступные способы по региону (providers.ready).

### 3.6 Админка (минимум)

- Ручное продление/активация тарифа владельцем.
- Возврат (refund) через API провайдера.
- Журнал событий оплат: `payment_events` (id, provider, event_id, type, user_id, amount, created_at).

## 4. Технические правила

```
1. Никаких новых фреймворков и сборки. Чистый Node + существующие файлы/стиль.
2. Секреты — только в /opt/goodgrowth/repo/.env (chmod 600), образец: .env.example
3. Карточные данные не хранить и не логировать. Только id платежей провайдера.
4. Все вебхуки: проверка подписи/источника + идемпотентность + 200 на повтор.
5. HTTPS обязателен (у нас nginx + Let's Encrypt).
6. Логи без секретов: '[pay] yookassa event payment.succeeded id=…'.
7. Код должен проходить `node --check` и не ломать существующие маршруты.
8. Перед изменениями — бэкап: cp server.js /root/bak/…; после — `systemctl restart goodgrowth`.
```

## 5. Как проверяем (приёмка)

```
1. Тестовая оплата в песочнице каждого провайдера → тариф включается
2. Повторный вебхук с тем же id → продления нет (идемпотентность)
3. Неверная подпись вебхука → 400, тариф не меняется
4. Отмена подписки → по окончании периода тариф возвращается на start
5. Возврат платежа → подписка корректируется, событие в журнале
6. Оплата по партнёрской ссылке (?ref=КОД) → срабатывает db.partnerAccrue
7. Мобильный вид страниц оплаты проверен
8. Отчёт: что сделано, какие ключи в .env, как ротировать, как откатить
```

## 6. Партнёрская программа (важно)

При успешной оплате нужно вызвать:

```js
db.partnerAccrue(code, userId, planCode, priceRub, 'YYYY-MM')
```

где `code` — из cookie `gg_ref` (её ставит сайт при переходе по `?ref=КОД`), иначе партнёр не получит комиссию. Если cookie нет — пропустить. Это обязательный пункт приёмки.

```

· доступ к репозиторию/коду и БД (для чтения)
· мерчант-аккаунты и ключи: ЮKassa, Paddle, ArCa/Ameriabank (по мере получения)
· тестовые карты из песочниц
· контакт для вопросов (Telegram), ответ в течение дня
```

## 8. Этапы и оплата

| Этап | Что | Результат |
|---|---|---|
| 1 | Подписки в БД + создание платежа + ЮKassa + страницы | оплата картой РФ работает в песочнице |
| 2 | Вебхуки, продление, отмена, кабинет оплаты | подписка живёт, отмена работает |
| 3 | Paddle (Европа) | оплата картой ЕС в песочнице |
| 4 | ArCa/Idram (Армения) | оплата армянской картой (если есть мерчант) |
| 5 | Отчёт + документация + ротация ключей | принято |

Оплата по этапам, каждый этап принимается отдельно.
