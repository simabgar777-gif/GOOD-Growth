## Как выложить без Заи

```bash
# на сервере, из папки с deploy.sh
sudo ./deploy.sh                          # origin/main
sudo ./deploy.sh jessie/i18n-login        # конкретная ветка
```

Скрипт: **клонирование во временную папку** → бэкап → копирование → `nginx -t` → reload → проверка 200.
**При любой ошибке останавливается** и пишет команду отката.

> **Сервис не трогается.** Скрипт пишет только в `/var/www/app`. В `/opt/goodgrowth/repo`
> (живой `server.js`, `.env`, `data/goodgrowth.db`) он **не пишет ничего** — там нет ни `reset`,
> ни `checkout`, ни копирования.
>
> **История дефекта.** Первая версия делала `git reset --hard` в постоянной рабочей копии.
> Зая поймала: в `/opt/goodgrowth/repo` лежит живой `server.js` с **33 несохранёнными правками** —
> такой `reset` откатил бы монолит и **положил бы сервис**. Теперь постоянной рабочей копии
> на сервере **нет вовсе**: код клонируется во временную папку и удаляется после выкладки.
> Плюс сторож: если `APP_DIR` окажется **внутри** сервиса — скрипт откажется работать.

## Пять фактов от Заи (первая рука, 25.10.2026)

1. **Бэкапы по операциям живут в `/root/bak/`** — папки `o58-*…o83-rail`, плюс `deploy-*` от deploy.sh. Это святое: каждый деплой обязан докладывать свою папку туда, откат любой правки делается из них за секунды.

2. **server.js — монолит, все роуты в одном файле** (`/opt/goodgrowth/repo/server.js`), сервис systemd `goodgrowth`, порт 3000. Правки — точечными якорями с проверкой `s.split(anchor).length-1===1`; после правки сверять число вхождений роутов до/после (route-drift). Рестарт: `systemctl restart goodgrowth`. База SQLite: `/opt/goodgrowth/repo/data/goodgrowth.db` (sqlite3 CLI нет — python3 или node).

3. **nginx-локейшены со своим alias обязаны иметь `default_type text/html;`** — иначе страница скачивается вместо открытия (уже ловили на /app/schedule). Конфиг: `/etc/nginx/sites-available/goodgrowth`; после правки всегда `nginx -t` затем `systemctl reload nginx`. Нестандартная статика вынесена в exact-локейшены: /style-c.css /theme.css /theme.js /blocks.css /rail.css /rail.js /i18n/.

4. **SMTP в коде готов, но выключен** — в .env нет SMTP_* ключей, /api/health честно отвечает "smtp":"off". Письма (сброс пароля, приглашения) идут через Telegram-бота. НЕ включать SMTP без пароля приложения от Капитана. ЮKassa не подключена (юр.статус), биллинг работает в ручном режиме.

5. **Пароли/токены в чат не печатать никогда** — только пути. Рабочие токены: SSH root (файл .ggtoken у Заи локально), TELEGRAM_BOT_TOKEN в /opt/goodgrowth/repo/.env (не в git, .gitignore закрывает). При деплое deploy.sh не трогает .env и data/ — так и должно быть.
